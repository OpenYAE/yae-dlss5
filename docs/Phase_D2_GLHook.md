# Фаза D2 — glhook: перехватчик OpenGL, который знает кадр DS2

> **Статус (2026-10-08):** план утверждён пользователем 2026-10-08. Отчёт исследования
> (`reports/Нейрорендеринг и трассировка пути для YAE.md`) принят «в целом»; решения программы P1–P12
> (`project-empty/docs/NR_PT_Program.md`) приняты — явно P6 (v2: glhook + свой хост — да), остальные по
> рекомендации. Открыты вопросы Q1–Q8 ниже (у каждого — рекомендация). Железо (2026-10-08): Linux и Windows
> с игрой — один ПК: сборка x86 кросс-компилируется на Linux (llvm-mingw), запуск и замеры — в окне Windows. Разведка статическая: код и тесты
> `yae-QindieGL` (на `e91be7b`), публичные заметки RE `yae-research` (на `476fc29`), декомпиляция
> `ds2render.dll` в `yae-research-private` (цитируется только адресами функций — выдержки из неё не
> выходят), данные игры (`gameres/materials`, `config_engine/ds2engine.cfg` в копии пользователя —
> только чтение), исходники DLSS5-Feeder v1.18.0-beta.2 и `dlss5-neural-amd` v0.7.10. На нативном
> драйвере кадр DS2 ещё не записывался: первая подфаза (D2.0) — приёмка контракта C5 с переписью кадра.

> **Цель.** Дать NR честные входы на оригинальной игре: цвет до HUD, глубину, векторы движения камеры
> из глубины и матриц, маски того, что движением камеры не объяснить, и (по желанию) джиттер для
> временного сглаживания — а HUD вернуть поверх результата неизменным. Вне игрового процесса (меню,
> ролики, загрузки) — кадр как без glhook, бит в бит.

> **Принцип.** DS2 не трогаем: всё — на границе OpenGL, куда `ds2render.dll` и так ходит через
> `opengl32.dll` из папки игры. Знание о виде DS2 не угадываем, а берём у yae-QindieGL — это контракт
> C5 программы, документ `yae-QindieGL/docs/DS2View.md` (подфаза QindieGL H.10) с кодом и тестами
> QindieGL за ним; первая подфаза D2 принимает этот документ, сверяя его с кадром на нативном драйвере
> (D2.0), и только потом пишется захват. Никакой зависимости от `yae-neural` до D3: фаза идёт против
> эхо-хоста и хоста с отказами. Изображения и векторы glhook не переворачивает: по контракту кадра C2 он
> объявляет начало координат в нижнем левом углу (`YN_ORIGIN_BOTTOM_LEFT`), а переориентация, если
> нужна, — дело потребителя ([Spec_BridgeProtocol.md](Spec_BridgeProtocol.md) §1, §4.9).

## Как устроено

### Схема

```
YOU_ARE_EMPTY.exe (x86)
  ds2render.dll ──► opengl32.dll = glhook ──► системный opengl32.dll (или next_opengl32, Q7)
                      │ теневое состояние: стеки матриц, классы проекций, камера, blend/depth/stencil,
                      │   вьюпорт, ножницы, контексты, списки отображения
                      │ модель кадра (ds2view): тени → небо → мир → оружие → частицы/декали | граница | HUD
                      │ точка захвата → слот YNB: цвет, глубина, векторы, флаги истории, маска
                      │ после захвата: отрисовки → слой HUD (C, W, копия глубины-трафарета)
                      │ wglSwapBuffers: композит (выход NR | захваченный цвет) ⊕ слой HUD → оверлей →
                      │   настоящий wglSwapBuffers
                      └──── YNB (Spec_BridgeProtocol.md) ──► ynb-loopback-host64 (D2) / yae-nr-host64 (D3)
```

В репозитории: `glhook/` (MSVC, x86 DLL под именем `opengl32.dll`), `glhook/ds2view/` (классификация
вида DS2 — платформонезависимый C++ с модульными тестами на записанных потоках вызовов, поэтому
проверяется и на Linux), `shared/ynb/` (структуры протокола с `static_assert`, общие для обеих
сторон), `tools/ynb/` (эхо-хост x64, хост с отказами, клиентский стенд x86).

### Какие вызовы перехватываются и зачем

Все ~371 экспорт прокси (поверхность GL 1.1 + WGL, R22) пересылаются в следующий `opengl32.dll`;
наблюдаются только группы ниже. Собственные GL-вызовы glhook идут напрямую по указателям следующего
модуля и никогда — через собственные экспорты: у `dlss5-neural-amd` собственный `glBindFramebuffer`,
вернувшийся через хук в обработчик, уже державший мьютекс, закрыл игру (R25).

| Группа | Вызовы | Зачем |
|---|---|---|
| Контексты и кадр | `wglCreateContext`, `wglDeleteContext`, `wglMakeCurrent`, `wglSwapBuffers` (через него идёт `SwapBuffers` из gdi32), `wglShareLists` | окно против pbuffer (HDR, снимки кубокарт), граница кадра, смена контекста → новое поколение YNB |
| Формат пикселя | `wglChoosePixelFormat`, `wglDescribePixelFormat`, `wglSetPixelFormat`, `wglGetPixelFormat`; наблюдение за `wglChoosePixelFormatARB` и функциями pbuffer | +8 бит трафарета к запросу DS2 (Q3); pbuffer-контексты помечаются как внеэкранные |
| Расширения | `wglGetProcAddress` | вернуть обёртки для тех функций расширений, что нужно видеть: `glDrawRangeElementsEXT`, `glMultiDrawArraysEXT`/`ElementsEXT`, `glBlendFuncSeparateEXT`, `glBlendEquationEXT`, `glBindBufferARB`, `glBufferDataARB`/`SubDataARB`, `glMapBufferARB`, `glBindProgramARB`, `glLoadTransposeMatrixfARB`/`glMultTransposeMatrixfARB`; остальное — указатель драйвера как есть |
| Матрицы | `glMatrixMode`, `glLoadIdentity`, `glLoadMatrixf/d`, `glMultMatrixf/d`, `glPushMatrix`, `glPopMatrix`, `glTranslate*`, `glRotate*`, `glScale*`, `glFrustum`, `glOrtho`; `glGetFloatv`/`glGetDoublev` для `GL_MODELVIEW_MATRIX` и `GL_PROJECTION_MATRIX` | теневые стеки; камера = первое преобразование на глубине 0 после `glLoadIdentity` (R1); класс проекции; внедрение джиттера и выдача DS2 проекции без джиттера |
| Состояние | `glEnable`/`glDisable` (DEPTH_TEST, BLEND, ALPHA_TEST, SCISSOR_TEST, STENCIL_TEST), `glDepthMask`, `glDepthFunc`, `glDepthRange`, `glBlendFunc`, `glColorMask`, `glViewport`, `glScissor`, `glPushAttrib`/`glPopAttrib` | класс отрисовки; режим смешивания для слоя HUD; угол теней по вьюпорту; после `glPopAttrib` теневое состояние помечается грязным и перечитывается |
| Отрисовки | `glBegin`/`glEnd`, `glDrawArrays`, `glDrawElements`, `glDrawRangeElements(EXT)`, `glMultiDraw*EXT`, `glCallList`/`glCallLists` | классификация, точка захвата, класс трафарета, перенаправление в слой HUD |
| Чтение кадра | `glCopyTexSubImage2D`, `glCopyTexImage2D`, `glReadPixels`, `glCopyPixels` | после мира — триггер захвата или барьер (ниже) |
| Очистки | `glClear` | начало кадра, угол теней, очистка мира |
| Списки | `glNewList`/`glEndList` | записать влияющие на состояние операции списка (матрицы, смешивание, глубина) и проиграть их в теневом состоянии при `glCallList` — идея `DL_RECORD` QindieGL (R16) |

### Модель кадра DS2 и точка захвата

Кадр — между двумя `wglSwapBuffers` на DC окна. Отрисовки в pbuffer-контекстах (HDR, кубокарты) не
классифицируются: это внеэкранная работа. Класс каждой отрисовки в окне решает `ds2view` по теневому
состоянию:

| Класс | Признак | Источник |
|---|---|---|
| `SHADOW_PASS` | аффинная (орто) проекция, до первой мировой отрисовки кадра, вьюпорт — угол у левого края с y = H − size − 30; всё между очисткой угла и его `glCopyTexSubImage2D` | R6 |
| `SKY` | проекция класса мира, камера на глубине 0 — только вращение с вращением главной камеры, запись глубины выкл. | R5, R7 |
| `WORLD_STATIC` | проекция мира, главная камера, глубина стека 0 | R1 |
| `WORLD_OBJECT` | проекция мира, главная камера, глубина стека ≥ 1 (матрица объекта) | R1 |
| `DYNAMIC` | `WORLD_OBJECT`, чья матрица объекта изменилась с прошлого кадра для того же ключа, или чьи вершины обновлены в этом кадре (скиннинг на CPU) | см. «Маски» |
| `WEAPON` | перспектива другого класса (ближняя ≈ 1, дальняя 200 или 500), после мира | R8 |
| `PARTICLE` | проекция мира, смешивание `add` (или частичные режимы R11), запись глубины выкл. | R11 |
| `DECAL` | проекция мира, `modulate` поверх мира, запись глубины выкл. | R11; `rtx.conf:46` |
| `SECOND_CAMERA` | перспектива с камерой, которая не главная и не её вращение (`!` в переписи) | R3, R5 |
| `HUD` | аффинная проекция (орто или тождественная) и тест глубины выкл., после мира | R4, R5, R12 |
| `FRAME_READ` | `glCopyTex*`, `glReadPixels`, `glCopyPixels` из кадрового буфера окна | R14 |

**Главная камера и класс мира** предсказываются по прошлому кадру (перепись QindieGL: главный
перспективный сегмент — тот, где больше всего отрисовок) и подтверждаются в текущем; в первом кадре
после загрузки — по первой перспективной отрисовке с тестом глубины и ближней плоскостью мира.

**Точка захвата** — первое из событий, наступившее **после начала мировой фазы** (в кадре была хотя бы
одна отрисовка `WORLD_STATIC` или `WORLD_OBJECT`):

1. отрисовка класса `HUD`;
2. чтение кадра (`FRAME_READ`) — захват делается **до** чтения;
3. `wglSwapBuffers` — мир без HUD (катсцены: `hud_render 0`, R19).

Что эту точку ломает и что делаем:

| Случай | Что происходит | Ответ |
|---|---|---|
| Проход теней в начале кадра (орто, запись глубины выкл.) | первая орто-отрисовка кадра — не HUD (R6) | правило «после начала мировой фазы» + угловой вьюпорт |
| Орто-отрисовки внутри мира (вспышки, фильтры в середине) | захват раньше, чем кончился мир | безопасно: всё после захвата идёт в слой HUD с тестом по копии глубины, и композит остаётся точным; теряется только NR на поздних мировых отрисовках (счёт — D2.0) |
| Экранные фильтры урона, размытие подбора (R13, R14) | чтение кадра после мира, затем полноэкранная отрисовка | захват до чтения; непрозрачный фильтр в слое закрывает NR целиком (кадр как в оригинале), смешанный (`flash`, `add`) ложится поверх NR |
| Меню, ролики, загрузки | мировой фазы нет | прозрачная передача, бит в бит |
| 3D-меню (уровень `menu`) | мир есть | распознаётся по шаблону кадра из D2.0; по Q4 — прозрачная передача |
| Катсцены | мир без HUD | захват на `wglSwapBuffers`; склейка камеры → сброс истории |
| Затемнения (полноэкранный квад с альфой) | отрисовка `HUD` | точно ложатся в слой |
| Пауза и меню поверх мира | мир + HUD | NR под меню |
| HDR (`hdr 1`) | мир рисуется в pbuffer, в окне — только квад тонального отображения и HUD | в окне нет мировой фазы → прозрачная передача до D2.9 (Q5) |
| Смена контекста, Alt-Tab, смена размера | новое поколение YNB (Spec §9) | прозрачная передача до готовности |

### Слой HUD

После точки захвата отрисовки идут не в задний буфер, а в FBO слоя из трёх целей:

- **`C`** — RGBA16F, цвет HUD на чёрном фоне (начало кадра: 0);
- **`W`** — RGBA16F, вес сцены по каналам (начало: 1; может стать отрицательным — режим `subtract`);
- **`DS`** — D24S8, копия глубины и трафарета кадра в точке захвата, чтобы поздние отрисовки с тестом
  глубины вели себя как на заднем буфере.

Композит при `wglSwapBuffers` — один полноэкранный проход: **`out = clamp(S ⊙ W + C)`**, где `S` —
выход NR (или захваченный цвет в прозрачной передаче).

**Почему точно.** Любое смешивание DS2 из R11, кроме `min` и `max`, имеет вид
`out′ = α ⊙ out + β`, где `α` и `β` зависят только от источника. Если до отрисовки
`out = S ⊙ W + C`, то после неё `out′ = S ⊙ (α ⊙ W) + (α ⊙ C + β)`. Значит:

- цель `C` смешивается **ровно тем состоянием, которое выставила игра** — это её же кадр, только на
  чёрном фоне;
- цель `W` смешивается тем же состоянием **без свободного члена** `β`: исходный множитель заменяется на
  ZERO, кроме случая, когда он сам `DST_COLOR`.

Фиксированный конвейер раздаёт цвет фрагмента во все цели рисования, а `glBlendFuncSeparatei`,
`glBlendEquationSeparatei` и `glEnablei` (GL 4.0, R26) дают каждой цели своё состояние:

| Режим DS2 (R11) | Состояние игры | Цель `C` | Цель `W` | Точно? |
|---|---|---|---|---|
| нет (непрозрачный) | смешивание выкл. | смешивание выкл.: `C = src` | ZERO, ZERO: `W = 0` | да |
| `blend` | SRC_ALPHA, ONE_MINUS_SRC_ALPHA | как у игры | ZERO, ONE_MINUS_SRC_ALPHA | да |
| `add` | ONE, ONE | как у игры | ZERO, ONE (без изменений) | да, кроме насыщения |
| частицы | ONE_MINUS_SRC_ALPHA, ONE; SRC_ALPHA, ONE | как у игры | ZERO, ONE | да, кроме насыщения |
| `modulate` | DST_COLOR, ZERO | как у игры: `C · src` | DST_COLOR, ZERO: `W · src` | да |
| `inv_subtract` | ONE, ONE, REVERSE_SUBTRACT | как у игры: `C − src` | ZERO, ONE (без изменений) | да, кроме отсечения в 0 |
| `subtract` | ONE, ONE, SUBTRACT | как у игры: `src − C` | ZERO, ONE, SUBTRACT: `−W` | да, кроме отсечения в 0 |
| `min`, `max`; множители `DST_ALPHA`, `ONE_MINUS_DST_*`, `SRC_ALPHA_SATURATE` | — | — | — | нет → барьер |

Отклонение возможно только там, где оригинал насыщал 8-битный буфер между отрисовками (например,
`add` поверх яркого фона и затем `blend` поверх) — его меряет приёмка D2.2. DS2 не пользуется альфой
назначения (R11), так что альфа заднего буфера не нужна.

**Барьеры.** После точки захвата:

- *чтение кадра*, когда слой ещё пуст, — просто разрешается: задний буфер и так содержит захваченный
  кадр;
- *чтение кадра*, когда в слое уже что-то есть, или *непредставимое смешивание* — слой сначала
  «сплющивается»: композит с `S` = захваченный цвет пишется в задний буфер (кадр становится ровно
  таким, как в оригинале к этому моменту), слой сбрасывается (`W = 1`, `C = 0`), операция выполняется
  на заднем буфере, дальше снова слой. Такой кадр помечается `BARRIER` и показывается без NR;
- *ARB-программы фрагментов* после захвата (экранные фильтры, `use_shaders 1`) — барьер, пока D2.2 не
  проверит, что `result.color` без опции `ARB_draw_buffers` раздаётся во все цели.

Частоту барьерных кадров считает D2.0; если она окажется высокой, вернётся отвергнутый сейчас
повтор команд HUD (см. «Исключено»).

**Свежесть HUD.** При конвейерной передаче результат кадра n появляется в кадре n+1. По умолчанию (Q2)
к нему прикладывается слой HUD того же кадра n — картинка согласованная, на кадр позже целиком; поэтому
слоёв два. Переключатель оверлея кладёт свежий слой кадра n+1.

### Захват: цвет, глубина, трафарет

В точке захвата, под охраной состояния (кадровые буферы, буфер чтения/рисования, ножницы и
`GL_FRAMEBUFFER_SRGB` выключены на время копий — приём фидера, R24):

1. **Цвет:** `glBlitFramebuffer` из заднего буфера окна в общую текстуру `RES_COLOR` слота, строка в
   строку — **без отражения** (строка 0 — низ экрана; объявлено `ORIGIN_BOTTOM_LEFT`).
2. **Глубина и трафарет:** копия кадрового буфера окна в текстуру `DS` (D24S8): `glCopyTexSubImage2D`
   (для формата DEPTH_STENCIL копирует оба) или блит глубины+трафарета — форматы совпадают, раз формат
   пикселя D24S8 (Q3); какой путь надёжен у вендора — решает D2.3.
3. **Один полноэкранный проход** (фрагментный шейдер, GLSL 3.30 в контексте compatibility) читает `DS`
   через два представления текстуры — глубину и трафарет (GL 4.3, `GL_DEPTH_STENCIL_TEXTURE_MODE`) — и
   пишет в цели FBO общего слота: `RES_DEPTH` (R32F, глубина окна как есть), `RES_MOTION` (RG16F),
   `RES_MOTION_FLAGS` (R8), `RES_CONTROL_MASK` (R8).
4. **Сигнал** `fence_in = n` со списком текстур слота и прочитанных выходов, `glFlush`, запись слота,
   `FRAME` (Spec §5.3).

Стоимость прохода на GPU при 1080p — порядка десятой доли миллисекунды (**оценка**); D2.3 меряет
запросами таймера.

### Векторы движения камеры

Всё — в собственных координатах изображения, то есть в оконных координатах GL (начало — нижний левый
угол, `+y` вверх), как требует контракт C2 для `YN_ORIGIN_BOTTOM_LEFT`:

- центр пикселя `p = (x + 0.5, y + 0.5)`, `x ∈ [0, W)`, `y ∈ [0, H)` — номер строки снизу;
- `d` — глубина окна в `p` (мировые отрисовки идут при `glDepthRange(0, 1)`);
- `ndc = (2·p.x/W − 1, 2·p.y/H − 1, 2·d − 1)`;
- **геометрия** (`d < 1`): `c′ = R · (ndc, 1)`, где `R = P_prev · V_prev · (P_cur · V_cur)⁻¹` —
  одна матрица 4×4 на кадр, считается на CPU в двойной точности;
- **фон и небо** (`d = 1`: небо рисуется без записи глубины, R5, R7): точка на бесконечности,
  `c′ = R_rot · (ndc.x, ndc.y, 1, 1)`, где `R_rot = P_prev · rot(V_prev) · rot(V_cur)⁻¹ · P_cur⁻¹` —
  точно для камеры неба, которая только вращается;
- `p_prev = ((c′.x/c′.w + 1)·W/2, (c′.y/c′.w + 1)·H/2)`; **`mv = p_prev − p`** — пиксели входного
  разрешения, от текущего к прошлому (`prev = cur + mv`), `+y` вверх;
- `V` — преобразование главной камеры на глубине 0 (R1), `P` — проекция мира **без джиттера**;
  `P_prev`, `V_prev` — прошлого отправленного кадра; все четыре матрицы уходят и в запись слота
  (Spec §6.2: нужны хосту при передаче через CPU, где он считает векторы сам);
- точность RG16F: при `|mv| < 64` пикселей шаг не грубее 1/32 пикселя (расчёт по 10-битной мантиссе).

**Оружие** (`WEAPON`): его глубина — в его собственной проекции и диапазоне, формула мира к ней не
применима. Модель оружия едет с камерой (тождественное преобразование модели, R8), поэтому
`mv = 0`; покачивание и отдача в v1 не передаются — их гасят маски.

**Склейки камеры:** скачок положения или поворота за кадр выше порога (порог — из записи D2.0)
ставит `SF_CAMERA_CUT` и сбрасывает историю. Смена угла обзора (прицеливание) склейкой не считается: её
учитывает `P_prev ≠ P_cur`.

**Синтетический поворот для приёмки.** Встроенного сценария камеры у DS2 нет (R20), поэтому у glhook
есть тестовый режим: в преобразование камеры на глубине 0 подмешивается известное вращение (рыскание
±2°, 0.25° за кадр) при поставленной на паузу игре. Ошибка перепроекции
`E(v) = mean |I_{n−1}(p + v) − I_n(p)|` по яркости, по статике (класс `WORLD_STATIC`) в центральных 60 %
кадра без растворений (где глубина прошлого кадра в `p + mv` не совпадает с текущей), считается для
`v = mv`, `v = 0` и `v = −mv`. Ограничение: DS2 отсекает геометрию по своей камере, поэтому подмешанный
поворот может обнажить края кадра — отсюда центральная область.

### Маски через трафарет

DS2 трафарет не использует (R9), поэтому glhook добавляет к формату пикселя 8 бит (Q3) и владеет ими
целиком: в начале мировой фазы — своя очистка трафарета, затем на каждой смене класса —
`glStencilFunc(GL_ALWAYS, класс, 0xFF)` и `glStencilOp(GL_KEEP, GL_KEEP, GL_REPLACE)`; до точки захвата и
на проходе теней тест выключен. Значение пишется там, где фрагмент прошёл тест глубины, — в том числе у
частиц без записи глубины; ближняя непрозрачная отрисовка поверх перезаписывает класс.

**Классы и то, что из них получается** (значения маски — **предложение**, их ставит пользователь по
листу A/B в D3):

| Класс | Значение трафарета | Векторы | Флаг истории | Маска NR |
|---|---:|---|---:|---:|
| ничего (очищено) / небо | 0 / 2 | вращение | 1 | 0.5 |
| статика мира | 1 | камера | 1 | 1.0 |
| объект на месте | 3 | камера | 1 | 1.0 |
| движущийся объект, актёр | 4 | камера | 0 | 0.6 |
| оружие | 5 | 0 | 1 | 0.5 |
| частицы, свечения | 6 | камера (фон) | 0 | 0.3 |
| декали | 7 | камера | 1 | 1.0 |
| вторая камера | 8 | 0 | 0 | 0.5 |
| полупрозрачное поверх мира | 9 | камера | 0 | 0.7 |

**Движущиеся объекты.** Ключ отрисовки объекта — (буфер вершин или указатель клиентского массива, первый
индекс и число, текстура); матрица объекта `O = V⁻¹ · MV`. Объект «движется», если `O` отличается от
прошлого кадра с тем же ключом, если его буфер вершин обновлён в этом кадре (`glBufferData`,
`glBufferSubData`, `glMapBuffer` — скиннинг на CPU), или если ключ новый (осторожный выбор на один
кадр). Флаг истории 0 у таких пикселей говорит модели не тянуть историю, а маска снижает эффект на
актёрах — это и есть «маска лиц и существ» P3 в v1.

### Джиттер Halton

Только когда хост объявил стадию сглаживания и пользователь её включил (`HELLO_JITTER`, `aa_request`):
NR — не TAA, и джиттер без накопления — просто дрожание. Последовательность Halton(2,3), 8 фаз при
родном разрешении (база NVIDIA для DLAA — 8 фаз, DLSS Programming Guide §3.7.1), смещения в пределах
±0.5 пикселя. Когда DS2 умножает проекцию мира или оружия на тождественную (R2), glhook домножает её
слева на перенос `T(2·j_x/W, 2·j_y/H, 0)` в NDC; `j` — в координатах изображения (снизу вверх, как
`+y` NDC). Орто- и тождественные проекции (HUD) и вид от света (тени) не трогаются. На
`glGetFloatv(GL_PROJECTION_MATRIX)` DS2 получает проекцию без джиттера. Векторы считаются по матрицам
без джиттера; сам джиттер уходит в `jitter_px` слота (Spec §6.2), в тех же координатах, что и векторы.

### Оверлей, A/B и прозрачная передача

- **Оверлей** — Dear ImGui (бэкенд OpenGL 3) рисуется после композита и до настоящего
  `wglSwapBuffers`: в захват NR и в слой HUD он не попадает никогда.
- **A/B** — на стороне клиента и мгновенно: захват и слой HUD продолжают работать, а при выключенном NR
  композит берёт `S` = захваченный цвет того же кадра — сравнение отличается только самим NR; хост об
  этом узнаёт из `nr_enabled`, но от него переключение не зависит.
- **Управление:** интенсивность, стиль, тон, структура, кожа, масштаб модели, стадия сглаживания,
  свежесть HUD, отладочные виды (векторы, классы трафарета, слой HUD, захват, разность), состояние
  (хост, бэкенд, модель, мс по стадиям, промахи, причина прозрачной передачи). Клавиши (Q6) опрашиваются
  `GetAsyncKeyState` на потоке рендера — это не зависит от того, как DS2 читает ввод; мышь для открытого
  оверлея — через подклассирование оконной процедуры. Настройки — в `yae-nr.ini`.
- **Прозрачная передача** — когда в кадре нет мировой фазы, хост не готов или упал, путь HDR (до D2.9),
  контекст не поддержан или glhook выключен целиком (`enabled=0` в `yae-nr.ini`): ни захвата, ни
  перенаправления, ни классов трафарета, ни джиттера — кадр как без glhook. Добавленные биты трафарета остаются (формат выбирается при создании
  контекста), и та же проверка «0 различающихся пикселей» доказывает, что они невидимы.

`yae-nr\logs\glhook.log`: при старте — GL renderer, версия и профиль контекста, расширения, формат
пикселя запрошенный и выбранный, LUID; раз в 600 кадров — шаблоны кадров, доли классов, успешность
захвата, барьеры, причины прозрачной передачи, CPU glhook на кадр, GPU проходов захвата (запросы
таймера); строки клиента YNB (Spec §11); каждая ошибка GL в собственной работе — со стадией. Режим
переписи (D2.0) пишет новые классы проекций, камер и шаблоны кадров, как перепись QindieGL; по клавише —
трассировка одного кадра: класс, матрицы и состояние каждой отрисовки. Фильтр необработанных исключений
называет модуль и смещение и передаёт управление дальше.

### Что берём у QindieGL и как (контракт C5)

Источник — **`yae-QindieGL/docs/DS2View.md`** (подфаза QindieGL H.10, по-английски): правило камеры,
классы проекций и виды матриц, камера неба, проекция оружия, силуэтный проход 512×512, признаки границы
«мир → HUD», лампы в мировых координатах под камерой — каждое со ссылкой на код и держащий его тест
(`yae-QindieGL/docs/PhaseH_RemixNR.md:228-237`, `:272`). D2.0 принимает документ.

**Что D2 нужно от `DS2View.md`** (список сверки D2.0):

1. Правило камеры: что считается сбросом modelview (`glLoadIdentity`, `glLoadMatrix` на глубине 0,
   опустошение стека), какое преобразование — вид, как ведут себя `glPushMatrix`/`glPopMatrix` и отрисовки
   «в пространстве глаза».
2. Классы проекций: признаки перспективы, орто и тождественной; ближняя и дальняя плоскости мира (ближняя
   10 — R2; дальняя — конечная или бесконечная?) и всегда ли перспектива мира и оружия умножается на
   тождественную (от этого зависит внедрение джиттера).
3. Небо: камера только с вращением, рисуется первой, запись глубины выкл.; признак — отношение `~` к
   главной камере.
4. Силуэтный проход теней: когда (начало кадра), сколько раз за кадр при `r_mdl_fake_shadows 1`,
   вьюпорт и очистка угла, копия `glCopyTexSubImage2D`, орто-вид от света.
5. Граница «мир → HUD»: проекция HUD (орто или тождественная), состояние глубины у HUD, какие
   отрисовки бывают «орто внутри мира» и почему.
6. Оружие: проекция (угол, аспект 4:3, z 1/200 или 1/500), диапазон глубины (`depth_near`/`depth_far`
   из `set_model_first_person`), камера (тождественная?), порядок относительно мира и частиц.
7. «Вторая камера» (`!` в переписи): что это в DS2 — зеркала, порталы, что-то ещё.
8. Кадры без мира и особые: меню (включая уровень `menu`), ролики, загрузки, катсцены.
9. Для каждого правила — тест QindieGL, который его держит (его перенос — эталон D2.1).

| Знание | Где у QindieGL | Как у glhook |
|---|---|---|
| Камера = первое преобразование на глубине 0 после `glLoadIdentity` | `code/d3d_matrix.cpp:103-224` (`CameraTracking`) | перенос правила в `ds2view` без D3DX; те же сведения на отрисовку: поколение, число преобразований на глубине 0, «в пространстве глаза» |
| Классы проекций (`P`/`O`/`I`, ближняя/дальняя, угол) | `code/d3d_view_diagnostics.cpp:95-125`, `232-250` | перенос (вход — матрицы GL по столбцам, транспонирование D3D убрано) |
| Виды камер и отношение к главной | `:252-309`, `:360-427` | перенос |
| Флаги границы мира и HUD | `:548-611` | перенос в оперативный классификатор (предсказание по прошлому кадру) |
| «Кадр в форме DS2» | `tests/camera_split_tests.cpp` | перенос в тест на GL-стенде (скрытое окно, настоящий драйвер) с ожидаемым классом каждой отрисовки |
| Запись операций списков | `code/d3d_lists.cpp` (`DL_RECORD`) | только идея: операции состояния и матриц внутри списков |
| Расширение маски CPU | `code/d3d_global.cpp:964-995` | не нужно в процессе игры: хост запускается с системной маской (Spec §2.2) |
| ProjectionFix, проективное текстурирование, RECT, эмуляция VBO | разные места | не нужно: glhook остаётся в GL, это делает драйвер |

Форма переиспользования — перенос с тестами (Q1): код QindieGL опирается на D3DX и стеки D3D9; его тесты
становятся эталоном поведения `ds2view`.

## Ограничения и риски

| Что | Риск / предел | Почему | Что делаем |
|---|---|---|---|
| Шаблоны кадра на нативном драйвере | неизвестны: сколько кадров с проходом теней, орто внутри мира, чтений кадра после мира | числа переписи QindieGL лежат в логах в папке игры (R4) | D2.0 записывает их до любого кода захвата |
| Контракт C5 | `DS2View.md` не готов или неполон к началу D2.0 | QindieGL H.10 пишется параллельно | D2.0 сверяет код и тесты QindieGL (R1–R5) и возвращает пробелы в H.10; закрытие — к M2 |
| Возможности контекста DS2 на AMD и Intel | смешивание по целям (GL 4.0), представления текстур и чтение трафарета (GL 4.3) могут отсутствовать | известно только для NVIDIA (R26) | D2.0 пишет версию и профиль; без GL 4.0 `modulate` и `subtract` становятся барьерами; без 4.3 — трафарет копируется отдельным путём |

| Движущиеся объекты | ошибки эвристики ключа | ключ строится по буферам и текстурам | осторожный выбор (новый ключ = движется); точность на размеченных кадрах — D2.4 |
| Оружие | покачивание и отдача не передаются | своя проекция, нет прошлых матриц модели | маска и история (таблица классов); объектные векторы — позже (Q8) |
| Синтетический поворот | края кадра, обнажённые отсечением DS2 | DS2 отсекает по своей камере | замер только в центральных 60 % |
| HDR-путь | без NR до D2.9 | мир в pbuffer квадратного размера (R10) | Q5 |
| Стоимость на CPU | теневое состояние на ~2150 отрисовок в тяжёлом кадре (R27) | каждая отрисовка классифицируется | цель ≤ 0.3 мс на кадр (**оценка**), меряется в D2.0 и D2.8 |
| Адресное пространство 32-битного процесса | импортированная память и цели слоя | 32-битная игра (`yae-QindieGL/STATUS.md:520-536`) | замер наибольшего свободного блока (D2.5, D2.8); `K` = 2, если надо |
| Барьерные кадры | показываются без NR | экранные фильтры читают кадр | частота — D2.0; при высокой частоте — повтор команд HUD |

делит с ней только машину с игрой. Внутри: D2.0, D2.1 (на «кадре в форме DS2») и D2.5 (по
спецификации, на стенде без игры) начинаются в первый день; D2.2 ждёт D2.0 и D2.1; D2.3, D2.4 и D2.7
идут параллельно после D2.2/D2.1; D2.6 — после D2.3 и D2.5; D2.8 — последней. Внешних блокирующих
зависимостей нет: `yae-neural` нужен только D3 (N1 — тождественный бэкенд для сантехники); контракт
C5 — `yae-QindieGL/docs/DS2View.md` — QindieGL пишет в H.10 сейчас, без игровой машины, а D2.0 его
принимает; пока документа нет, D2.0 и D2.1 опираются прямо на код и тесты QindieGL (R1–R5). Выход фазы —
веха M2 программы: цвет до HUD и векторы камеры через эхо-хост; к ней же закрываются пробелы C5.

## Исключено

- **Перехват функций `ds2render.dll` (Detours, двоичные патчи)** — граница GL стабильна и достаточна, а
  бинарники 2006 и 2019 годов различаются (`yae-research-private`, README).
- **QindieGL (GL → D3D9) как основа уровня R** — теряет родной рендер DS2: шейдерный путь отложен, HDR и
  карты нормалей выключены; остаётся резервом транспорта (QindieGL Phase K).
- **Захват через ReShade, как в v1** — кадр после HUD, матриц нет (R23).
- **Повтор команд HUD после NR** — точен для всего, но требует полного регистратора GL с копиями
  клиентских массивов; двухцелевой слой точен для всех режимов DS2 кроме `min`/`max`, поэтому повтор не
  нужен, пока барьерные кадры редки (их считает D2.0).
- **Маска HUD по разности кадров** (где HUD изменил пиксель — показать оригинал) — слишком осторожна для
  полупрозрачного HUD; оставлена отладочным видом и запасным путём для GPU без смешивания по целям.
- **Объектные векторы движения для актёров** (повторная отрисовка с прошлыми матрицами и костями) —
  позже (Q8); в v1 — маска без истории.
- **Оптический поток в glhook для движущихся объектов** — отвечает на мерцание света «уверенно неверным»
  вектором (`DLSS5_Feed.fx:41-46`); правильный путь — геометрия.
- **Переворот изображений и векторов в glhook** — по контракту C2 glhook объявляет нижний левый угол;
  переориентирует, если надо, потребитель.
- **`WGL_NV_DX_interop2` как основной транспорт** — модель «блокировка/разблокировка» и отдельное
  D3D11-устройство в процессе игры; только как проба для Intel перед передачей через CPU (Spec §10).
