# Фаза D1 — Укрепление цепочки v1: фидер протокола v11, OptiScaler wilsjo2, хеши, профили GPU, замеры

> **Статус (2026-10-08):** план утверждён пользователем 2026-10-08. Отчёт исследования
> (`reports/Нейрорендеринг и трассировка пути для YAE.md`) принят «в целом»; решения программы P1–P12
> (`project-empty/docs/NR_PT_Program.md`) приняты — явно P5 (модифицированные DLL для RTX 20/30/40 — только
> opt-in) и P6 (v2 — да), остальные по рекомендации. Открыты вопросы Q1–Q9 ниже (у каждого — рекомендация).
> Железо (2026-10-08): Linux и Windows с игрой — один ПК с RTX 5090; первые числа RTX 30 снимает
> RTX 3060 Laptop 6 ГБ (D1.8). Разведка статическая: файлы
> репозитория, импорт, строки (`strings`) и PE-заголовки поставляемых бинарников, исходники
> DLSS5-Feeder на теге v1.18.0-beta.2 (`3907e2b`) и `dlss5-neural-amd` v0.7.10 (`af465d3`), заметки
> исследования. Игра не запускалась — каждая подфаза начинается с замера (D1.0 — общий замер «до»).

> **Цель.** Цепочка v1 (ReShade x86 → DLSS5-Feeder → host64/D3D12 → OptiScaler → NGX) остаётся рабочим
> профилем уровня R, пока v2 (glhook D2 + хост D3) её не догонит. Для этого она должна стать
> воспроизводимой (каждый скачиваемый и поставляемый байт закреплён по SHA-256), актуальной (пара фидера
> протокола v11, живая ветка OptiScaler), консервативной по умолчанию, измеренной (миллисекунды по
> стадиям, уровням и GPU) и шире по железу: RTX 20/30/40 — по явному согласию, AMD — временный профиль.
> Это единственное место программы, где числа NR на RTX 20/30 можно получить до появления `yae-neural`.

> **Принцип.** Архитектуру v1 не трогаем: ни точку захвата (кадр с HUD), ни векторы движения (оптический
> поток) — это работа D2/D3. Каждое изменение сдаётся с числом «до» и «после» на одной конфигурации;
> откат — резервная копия установщика (`_DLSS5-Backups`). NR — по выбору пользователя, с мгновенным A/B
> (P3). Ни библиотеки NVIDIA, ни модифицированные сборки не попадают в git и в релиз (P4, P5).

## Как устроено

### Цепочка до и после фазы

```
YOU_ARE_EMPTY.exe (x86, OpenGL; CPU 0 — pin ds2kernel.dll)
  opengl32.dll = ReShade x86 6.8 ─► Lumenite_Kernel ─► DLSS5_Feed.fx (MV 1/8, глубина)
  dlss5-feed.addon32 ............ 1.16.0-beta.6 (v10) ──► 1.17.0 (v11)          [D1.2]
        │ именованный канал \\.\pipe\dlss5-feed.<pid> + общие D3D12-текстуры и фенсы
host64\dlss5-feed-host64.exe ..... 1.16.0-beta.6 ──► 1.17.0, маска CPU = системная [D1.2, D1.5]
  dxgi.dll   = ReShade x64 (+ yae-affinity.addon64 до выхода исправления upstream — Q5)
  winmm.dll  = OptiScaler DLSS-NR: Dagherbou 0.2.0 ──► линия wilsjo2 v0.8.92      [D1.3]
               nvngx.dll_dlssnr.dll (форвардер) ──► удалён (не нужен с v0.8.1)
  nvngx_dlss.dll   (310.9.1.0, по тегу и хешу)                                     [D1.1]
  nvngx_dlssnr.dll (310.8.0.0 подписанная — RTX 50; P5-сборка — RTX 20/30/40)      [D1.7]
```

### Закрепление каждого байта (D1.1)

- **`deps.lock.json`** в корне репозитория — одна запись на зависимость: имя, URL **по тегу или
  коммиту** (никаких `refs/heads`, `main`, `mainline`), SHA-256 архива и каждого извлекаемого файла,
  размер, репозиторий-источник. `Setup` читает только его. Файл, который уже лежит в
  `THIRD-PARTY-FILES-HERE\`, проходит ту же проверку хеша; «подписан NVIDIA» — дополнительное условие
  для официальных DLL, а не замена хеша (закрывает R3).
  - LumeniteFX — zip конкретного коммита (`codeload…/zip/<sha>`) и хеши пяти извлекаемых файлов и
    текстуры.
  - `nvngx_dlss.dll` — файл тега NVIDIA/DLSS `v310.9.1` (не ветки `main`) и его SHA-256.
  - `nvngx_dlssnr.dll` — как сейчас (архив `388C0A79…` и DLL `E16BCF15…`).
- **`payload/SHA256SUMS`** — хеш каждого поставляемого бинарника (ReShade, фидер, OptiScaler и его
  библиотеки). `Install` сверяет их до копирования: битая или частичная выгрузка репозитория → отказ
  (закрывает R6).
- **Однострочник** (`install.ps1`) качает zip релизного тега и сверяет его SHA-256, записанный в самом
  `install.ps1`. Сам `install.ps1` приходит из `main` — это корень доверия, и он назван в README
  честно (R2, R5).
- **Проверка-гейт** `tools/Check-Pins.ps1`: 0 вхождений `refs/heads/`, `/main/`, `mainline` в URL
  скриптов и README; отказ установки при подмене одного байта в любой зависимости.

### Пара фидера и потребитель NR (D1.2, D1.3)

Обе половины фидера, `DLSS5_Feed.fx` и `Verify-DLSS5Feeder.ps1` берутся из одного релиза (Q1) и
заменяются одним коммитом: протокол v11 не совместим с v10 (R9). В `dlss5-feed.cfg` добавляются ключи
1.17 со значениями по умолчанию (`settle_evals=0`, `hold_strength=0`, `hold_tolerance=0.04`); остальные
ключи не меняются. В той же замене `winmm.dll` (OptiScaler.dll под именем, которое импортирует хост)
становится сборкой линии wilsjo2 v0.8.92 (Q2); `nvngx.dll_dlssnr.dll` удаляется; `OptiScaler.ini`
переносится на шаблон новой сборки с ключами, которые требует README фидера: `[DlssNr] Enabled=true`,
`[Upscalers] Dx12Upscaler=dlss`, `[DlssNr] FinishedPicture=false` (иначе проход уходит в Present
окна хоста, которого игра не видит), `[ProcessFilter] TargetProcessName=auto`. Признак успеха в логе
хоста — `direct-runtime build`, `neural model (feature 18) loaded`, затем регулярные `DLSS-NR running`
/ `DLSS-NR cost`.

### Значения по умолчанию и A/B (D1.4)

Стартовая точка (Q3) — значения NVIDIA для NR в Remix (R14), которые заметно консервативнее
«нейтральных» значений сообщества (тон и структура 1.0): `LocalStructure` 0.7, `LocalTone` 0.3;
`Intensity` 0.8 (наше предложение — у Remix 1); `SkinStructure` −1 (следовать структуре) и `AutoMask`
true, пока нет масок материалов (их даст только D2/D3); `MaxRatio` 2.0 остаётся: для тёмной игры этот
предохранитель важнее всего — модель «превращает яркий свет в цепочку цветных ячеек» (R13). Клавиша A/B —
`[DlssNr] ToggleKey` OptiScaler (сейчас не назначена); выбрать клавишу, не занятую DS2, по таблице
биндов игры, записать в README.

### Сродство хоста и LAA (D1.5)

**Замер.** Пока игра идёт: маска процесса `dlss5-feed-host64.exe` и игры
(`Get-Process … | Select ProcessorAffinity`), загрузка ядер по потокам хоста (Process Explorer), p50/p99
времени кадра (PresentMon) на самом тяжёлом уровне протокола D1.0 — до и после расширения маски.
Ожидание по R20: у хоста маска 1.

**Исправление (Q5).** Хост расширяет свою маску до системной при старте
(`GetProcessAffinityMask` → `SetProcessAffinityMask(GetCurrentProcess(), system)`; маска может быть
шире родительской — достаточно, чтобы она была подмножеством системной). Это ~10 строк в
`host/dlss5-feed-host64.cpp` — предложить PR автору фидера (MIT, активен). До выхода — крошечная
ReShade-надстройка `yae-affinity.addon64` в `host64\` (ReShade x64 хоста грузит надстройки из своей
папки), которая делает то же при загрузке. Игре маску не трогаем: это выбор DS2.

**LAA.** Установщик и верификатор читают флаг `IMAGE_FILE_LARGE_ADDRESS_AWARE` (0x0020) в PE-заголовке
`YOU_ARE_EMPTY.exe` и сообщают его. Замер адресного пространства — внешний 64-битный скрипт
`tools/Get-AddressSpace.ps1` (`VirtualQueryEx` по процессу игры): наибольший свободный блок и свободное
всего, раз в 10 с, за сеанс из 5 локаций подряд. Если наибольший блок падает ниже 64 МиБ (порог —
предложение), установщик рекомендует LAA-патч (Q4); патч — отдельной командой, с резервной копией EXE и
записью хешей до/после, как у QindieGL (R22).

### Протокол замеров уровня R (D1.0, D1.8)

Протокол — общий для этой фазы и для лаборатории железа (P11); его же повторяют тестеры.

- **Конфигурация записывается целиком:** GPU (название, PCI device ID), драйвер, CPU, ОЗУ, сборка
  Windows, разрешение, значения `config_engine\ds2engine.cfg` (`hdr`, `use_shaders`, `stencil_bpp`…),
  профиль установки и хеши компонентов из манифеста.
- **Уровни (предложение):** `med1` (начало, интерьер), `kolhoz` (улица, туман), `meat` (завод), `metro`
  (тёмный тоннель), `theatre` (интерьер с источниками света) — из цепочки кампании, которую использует
  движок (`yae-engine/docs/Roadmap.md:52-56`). Для каждого — сохранение пользователя в фиксированной
  точке.
- **Прогон:** 30 с стоя + 30 с поворот мышью, NR выкл. и вкл. (клавиша A/B), по 3 повтора; затем 10 мин
  свободной игры — стабильность.
- **Инструменты:** PresentMon (времена кадров, CPU/GPU busy) для игры и для хоста; строки логов —
  `dlss5-feed.log` (раз в 600 кадров: CPU фидера на кадр, интервал кадра, запись в канал),
  `host64\dlss5-feed-host.log` («DLSS GPU … ms/frame»), `host64\OptiScaler.log` («DLSS-NR cost»);
  видеопамять — `nvidia-smi` / счётчики GPU Windows.
- **Стадии в таблице:** кадр игры без NR; CPU фидера в игре; DLAA + NR на GPU хоста; стоимость NR
  отдельно (OptiScaler); полный кадр с NR; видеопамять; p50/p95/p99.
- **Результат:** скрипт `tools/Measure-TierR.ps1` собирает CSV PresentMon и строки логов в CSV и JSON
  (поля — как у отчётов лаборатории: GPU, драйвер, дата, уровень, стадия, мс), сводная таблица — в
  `docs/measurements/` (Q9).

### Тёмные сцены и лист A/B (D1.6)

`AutoCapture` OptiScaler пишет до 8 парных кадров «до/после» (R13); для протокола их снимают на каждом
уровне в тёмных точках (плюс снимки экрана в режиме A/B). Скрипт `tools/Check-DarkScenes.py` по каждой
паре считает яркость Y (Rec. 709 по декодированным из sRGB значениям): p1 и p5 (уровень чёрного), долю
пикселей с Y < 0.02 и Y < 0.05 (доля почти-чёрного), среднее, p99 (света). Отчёт — по уровням, выкл. и
вкл., для старых значений (все 1.0) и для консервативных. Пороги — решение пользователя; предложение
(**оценка**, не норма): относительное изменение доли почти-чёрного ≤ 10 %, сдвиг p1 ≤ 2/255. Лист A/B —
сетка PNG: 5 уровней × {выкл., старые значения, консервативные}.

### Профили GPU (D1.7)

| Профиль | Как определяется | `nvngx_dlssnr.dll` | `WorkingScale` | Проверка |
|---|---|---|---|---|
| RTX 50 | имя адаптера «RTX 50…» + PCI device ID | подписанная 310.8.0.0, `E16BCF15…1FC8E` | 1.0 | подпись NVIDIA + хеш |
| RTX 40 | «RTX 40…» | P5: ShortFuse cross-generation, `E67DEE20…989A` (Q6) | 0.75 (**оценка**: путь Ada стоит в 1.5–3 раза дороже Blackwell по сообщениям; уточняется замером) | только хеш (подпись недействительна по построению) |
| RTX 20/30 | «RTX 20…», «RTX 30…» | та же P5-сборка (FP16-путь) | 0.5 | только хеш |
| Прочие NVIDIA (GTX) | — | — | — | отказ: DLAA фидера требует RTX (верификатор: «DLSS/NGX requires an RTX card») |
| AMD | vendor 0x1002 | — | — | профиль D1.9 или отказ с объяснением |
| Intel | vendor 0x8086 | — | — | отказ с объяснением (32-битного GL-пути нет ни у кого) |

**Согласие на P5** — явное: ключ `-AcceptModifiedRuntime` плюс интерактивное подтверждение с текстом:
это изменённая сборка NVIDIA-библиотеки, её подпись недействительна, она проверена только по хешу, её
источник такой-то. Сборка никогда не скачивается откуда попало: либо файл пользователя, либо зеркало при
точном совпадении хеша (Q6). Ни в репозитории, ни в релизе её нет (P4, P5).

### Временный профиль AMD (D1.9)

**Что это.** Установщик zmodelerlover (AMD-NR ReShade Installer v0.7.12, 2026-10-06) ставит ReShade как
32-битный `opengl32.dll`, `amd-nr.addon32` + `amd-nr-host64.exe`, рантайм и веса, проверяя каждый хеш
(R23). Наш установщик на AMD-GPU: объясняет ограничения, предлагает запустить установщик автора
(закреплённый по SHA-256) или даёт ссылку. Профили v1 и AMD взаимоисключающие — оба ставят ReShade как
`opengl32.dll`.

**Почему стоит (оценка ценности).** Первое — это единственный способ показать NR владельцу AMD в YAE до
M3. Второе, и для программы важнее: путь гоняет 32-битный GL-интероп AMD именно в этой игре (импорт
`D3D11_IMAGE`, конкретные версии Adrenalin) — данных, которых не хватает D2.5 и D3: для x86 + AMD измерен
только `D3D11_IMAGE`, а `D3D12_RESOURCE` — нет (`Spec_BridgeProtocol.md` §4.8 и §15). Третье — дёшево:
нашего кода — только определение GPU и текст.

**Почему ограниченно.** HUD обрабатывается вместе со сценой; только цвет; движение на 32-битных играх —
блочный оценщик, который, по журналу изменений автора, на текстурированной сцене при панорамировании
даёт шум, а рантайм отвечает потерей истории — эффект «гаснет и мерцает, пока камера движется» (их
v0.7.1); на RDNA2/3 — закрытый рантайм danielblnc с жалобами на зависания системы через 20–60 мин
(сторож автора снимает сеть после задания длиннее 2 с); проверено одним человеком на одной карте. Поэтому
— только opt-in «эксперимент», только при наличии тестера (Q7), и он уходит с появлением D3 (M3).

## Исключено

- **NVIDIA-DLL и модифицированные сборки в репозитории или релизе** — P4, P5; ставятся у пользователя по
  хешу.
- **Патчер dev-camo в установщике** — нужен CUDA Toolkit 13.3 и PTX внутри DLL, а по сообщению в
  OpenDLSS-NR #3 подписанная 310.8.0 содержит только кубины `sm_120` без PTX; противоречие источников не
  разрешено. Готовая сборка по хешу надёжнее (отчёт, раздел «RTX 20/30»).
- **`work_resolution` < 100** — на OpenGL-транспорте фидера он «зафиксирован на 100 %» (R10); рычаг
  стоимости — `WorkingScale` OptiScaler, который работает в хосте независимо от транспорта.
- **Синтетический джиттер DLSS фидера (`work_upscale=2`)** — только D3D11, по замеру автора стоит как
  100 % и мерцает.
- **«Геометрические векторы» `DLSS5_Feed.fx`** — экспериментальны и шумны, а HUD получает векторы камеры
  (R12); правильное решение — настоящие матрицы камеры в D2.
- **Потребители Deep Fried Chicken и renodx-dlss5** — распространяются через Discord, закрепить
  публичный источник по хешу нельзя.
- **Стабилизатор вывода фидера (`hold_strength`) по умолчанию** — экспериментальный; остаётся вариантом
  в листе A/B.
- **Хост фидера с OptiScaler-форком на AMD-рантайме (neural-amd-opti) как AMD-профиль v1** — хост фидера
  объявляет не-NVIDIA адаптер неподдерживаемым («NGX is NVIDIA's runtime and this is not an NVIDIA GPU»,
  строки хоста); не проверено и профилем не будет.
- **LAA-патч без согласия** — меняет EXE пользователя (Q4).
- **Профиль для GTX и прочих не-RTX NVIDIA** — DLAA фидера требует тензорных ядер.
